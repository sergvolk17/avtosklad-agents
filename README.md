# АвтоСклад Agents

Безопасная агентная платформа для автоматизации АвтоСклада на базе Hermes Agent.

## Что входит

- **Manager** — управляющий: принимает цель, дробит работу, назначает подагентов, собирает результат.
- **Pricing** — цены YACCO и других поставщиков, правила розница/опт, контроль двойной наценки.
- **Procurement** — закупки, дефицит, остатки и предложения по пополнению.
- **Tech** — GitHub, тесты, резервные копии, диагностика Docpart/SpaceWeb.
- **Content** — карточки, описания, SEO, новости.
- **Support** — клиентские ответы, статусы заказов и консультации.

## Базовый принцип безопасности

По умолчанию агенты работают в режиме анализа и подготовки изменений. Любое действие, которое может изменить продакшн, базу данных, цены, остатки, заказы, пользователей или файлы сайта, должно иметь отдельное явное подтверждение оператора.

## Быстрый старт

1. Установите Docker Desktop (Windows) или Docker Engine (Linux/VPS).
2. Скопируйте `.env.example` в `.env` и заполните только локально. Не коммитьте `.env`.
3. Запустите первичную настройку Hermes:

   ```bash
   docker compose run --rm hermes setup
   ```

4. Примените безопасные настройки проекта:

   ```bash
   ./scripts/bootstrap.sh
   ```

5. Запустите шлюз:

   ```bash
   docker compose up -d
   ```

6. Проверка:

   ```bash
   docker compose exec hermes hermes doctor
   ```

## Важно для АвтоСклада

- YACCO retail: закупочная цена +75%, округление до рубля.
- YACCO wholesale: закупочная цена +35%.
- Московский склад поставщика и физический склад Пыть-Яха считаются раздельно.
- Нельзя переносить московские остатки в Пыть-Ях.
- Нельзя применять наценку второй раз к уже рассчитанной розничной цене.
- Перед массовой записью цен/остатков обязательно формируется dry-run и резервная копия.

## Структура

- `AGENTS.md` — общие правила поведения Hermes в проекте.
- `skills/` — роли и процедуры агентов.
- `workspace/` — рабочая область для файлов и скриптов.
- `data/` — локальные входные данные, не секреты.
- `scripts/` — bootstrap и проверки.
- `docs/ARCHITECTURE.md` — архитектура и этапы внедрения.
- `docs/PRODUCTION_RUNBOOK.md` — как безопасно работать с продакшном.

## Этапы внедрения

**Этап 1 — read-only:** анализ сайта, прайсов, GitHub, логов и структуры Docpart.

**Этап 2 — controlled write:** агент готовит diff/SQL/файл импорта, человек подтверждает применение.

**Этап 3 — ограниченная автоматизация:** только обратимые операции с валидацией и журналом.

**Этап 4 — автономные рутины:** отчёты, мониторинг, уведомления, закупочные рекомендации, контент — без опасных самовольных изменений.
