# АвтоСклад App — функциональный слой V1

## Неприкосновенное правило дизайна
Текущий визуальный стиль приложения считается утвержденным.
При реализации V1 запрещено менять без отдельного решения владельца:
- цветовую систему;
- типографику;
- расположение основных экранов и навигации;
- общий визуальный язык карточек, кнопок и блоков;
- бренд АвтоСклад.

Работа V1 — только функциональность, данные, состояния, API и сценарии.

## Архитектура
Единый источник данных — магазин/Docpart и интеграционный API АвтоСклада.

Схема:
Пользователь приложения → AutoSklad App API → Docpart / локальный каталог / CRM / сервисы / платежи.

Не создавать параллельную независимую базу цен и заказов, если данные уже являются мастер-данными магазина.

## Модули V1

### 1. Авторизация и профиль
- вход клиента;
- регистрация;
- профиль;
- сохраненные адреса;
- тип клиента: розница / B2B;
- единый пользователь с сайтом;
- история заказов.

### 2. Гараж
- несколько автомобилей;
- VIN;
- марка / модель / год / двигатель;
- основной автомобиль;
- история обслуживания;
- сохраненные детали для автомобиля;
- повторный заказ.

### 3. Поиск запчастей
- поиск по артикулу;
- поиск по бренду + артикулу;
- VIN-запрос;
- аналоги / кроссы;
- предложения поставщиков;
- локальный склад;
- фильтр срок/цена/наличие;
- карточка товара.

### 4. YACCO и подбор масла
- отдельный каталог YACCO;
- подбор по автомобилю;
- официальный подбор масла через интеграцию;
- рекомендации моторное / трансмиссионное / антифриз / жидкости;
- фасовки;
- цена и наличие;
- быстрый повторный заказ.

### 5. Корзина и заказ
- корзина;
- несколько способов получения;
- самовывоз;
- курьер;
- службы доставки;
- комментарий;
- промокод;
- бонусы;
- оформление без потери данных при закрытии приложения.

### 6. Оплата
- единый платежный слой;
- онлайн-оплата;
- статус оплаты;
- возвраты;
- чек/касса;
- Честный знак для маркированных товаров через магазинную инфраструктуру.

### 7. Заказы
- статусы;
- состав;
- оплата;
- получение;
- трекинг;
- повторить заказ;
- обращение по заказу.

### 8. Уведомления
- push как основной бесплатный канал;
- e-mail fallback;
- SMS только для критичных событий при необходимости;
- новый заказ;
- оплата;
- изменение статуса;
- прибытие;
- отмена;
- акция/персональное предложение с настройкой согласий.

### 9. Лояльность
- бонусный баланс;
- история начислений;
- уровни;
- персональные цены;
- купоны;
- акции;
- реферальный код позже.

### 10. B2B
- кабинет ИП/ООО;
- реквизиты;
- договорные цены;
- персональная наценка;
- оптовый прайс;
- счета;
- повтор заказа;
- документы;
- менеджер.

### 11. Автосервисы
- каталог сервисов;
- услуги и цены;
- запись;
- дата/время;
- автомобиль из Гаража;
- передача заявки сервису;
- статусы;
- отзыв;
- монетизация: комиссия/лид/подписка/продвижение.

### 12. Чат и JARVIS
- чат с магазином;
- JARVIS как маршрутизатор вопросов;
- определение темы: заказ / подбор / сервис / B2B / возврат;
- передача человеку;
- история переписки.

### 13. Админ приложения
Отдельный контур в JARVIS:
- пользователи;
- активность;
- заказы из приложения;
- конверсия;
- push;
- сервисы;
- B2B;
- ошибки;
- релизы;
- roadmap.

## Контроль качества
Каждая функция должна иметь состояния:
- loading;
- success;
- empty;
- error;
- offline;
- retry.

Нельзя считать модуль готовым, пока нет проверки API, ошибок и пустых состояний.
