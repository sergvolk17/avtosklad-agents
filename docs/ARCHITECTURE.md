# Архитектура АвтоСклад Agents

## Контур управления

`Сергей (директор) → Manager → специализированные агенты → инструменты → проверка → изменение`

Manager не должен сам подменять предметного агента, если задача относится к ценам, закупкам, технике, контенту или клиентам. Его работа — декомпозиция, контроль конфликтов и итоговая проверка.

## Доступы

### Уровень A — безопасный, можно автоматизировать
- чтение публичного сайта;
- анализ прайсов;
- подготовка описаний;
- расчёт цен в локальном файле;
- GitHub read-only;
- отчёты и рекомендации.

### Уровень B — только после проверки
- создание веток/PR;
- загрузка подготовленных файлов в staging;
- изменение CMS-контента;
- обновление цен при неизменных остатках.

### Уровень C — только явное подтверждение директора
- SQL UPDATE/DELETE на production;
- изменение остатков;
- изменение заказов/платежей;
- изменение пользователей и прав;
- деплой на production;
- удаление файлов/товаров/категорий.

## Источники правды

- Код и конфигурации автоматизации: GitHub.
- Секреты: только защищённое окружение Hermes/secret store, не Git.
- Прайс поставщика: исходный файл поставщика.
- Локальный остаток Пыть-Яха: текущий склад Docpart, а не московский прайс.
- Изменения production: журнал + резервная копия + верификация после записи.

## Следующие интеграции

1. GitHub — проектный репозиторий и PR-процесс.
2. SpaceWeb — отдельный SSH-пользователь, сначала read-only.
3. Docpart — API/БД/поддерживаемые импорты после документирования схемы.
4. Telegram — канал директора для отчётов и подтверждений.
5. Поставщики — отдельные адаптеры прайсов и нормализация данных.
